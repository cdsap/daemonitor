Daemonitor

Activity Monitor for Gradle and Kotlin daemons

Live Monitor lists every Gradle-related JVM — daemons, wrappers, Kotlin daemons, and Gradle workers — with RSS, CPU, uptime, and memory-pressure badges. See what’s building now, what built recently, and whether an IDE, terminal, or coding agent started it.

macOS · Windows · Linux

Why it exists

IDEs, terminals, scripts, and coding agents can all start Gradle at once. Daemons and workers keep using CPU and memory after the visible build window closes. Daemonitor is a local Activity Monitor for those processes — RSS, CPU, uptime, and retained build history — without sending data off the machine.

What Daemonitor shows

Memory timeline

Rolling RSS charts next to configured heap (-Xmx) so concurrent Gradle processes are easy to compare.

Build History

Recent builds with duration, outcome, peak resources, invocation source, and coding-agent attribution when an agent triggered the build. Searchable local history.

Desktop app and CLI

Same local process data, two surfaces: a packaged desktop app, or a native terminal client for SSH and build machines.

Privacy

Local-first by design. History and process data stay on your computer.

  • No telemetry — nothing is phoned home about your builds or machine.
  • Local SQLite storage — history lives in a database on your computer.
  • Best-effort redaction — command lines and logs are redacted before storage.
  • Local read-only MCP — agent access stays on localhost and cannot mutate builds.

MCP

Optional local, read-only MCP so compatible tools can inspect retained build history and currently visible Gradle processes — without leaving the machine.
