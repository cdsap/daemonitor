# Daemonitor 1.3.1 — PreferGo retention hotfix

Replaces the broken `v1.3.0` cut for PreferGo History retention.

## Fix

In 1.3.0, PreferGo started `daemonitor-cored` without `-retention`, so the Go
default (**24h**) purged builds while Settings still showed the user's window
(often 15 days). History older than a day could disappear permanently.

**1.3.1:**

- Cored default retention is **15 days** (samples and builds).
- `/v1/health` reports `retention_ms` and `pid`.
- Desktop / CLI PreferGo starts cored with the user's Settings `retentionDays`.
- If a healthy cored is already running with a different window (including old
  1.3.0 cores that omit `retention_ms`), PreferGo restarts it once with the
  user's value.

Rows already deleted by the 24h purge are **not** recoverable.
